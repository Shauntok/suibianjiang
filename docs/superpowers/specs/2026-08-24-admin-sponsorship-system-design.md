# 小时代 Admin 运营后台与业配系统设计

日期：2026-08-24  
状态：已完成交互确认，待实现计划  
阶段：Alpha 0.4

## 1. 目标

本次改造包含两个相互关联的部分：

1. 将现有 Admin 首页整理成适合日常运营的工作台，让管理员能快速看见社区状态、待办、内容与业配数据。
2. 增加一套默认关闭、可人工控制、重视阅读体验与隐私的商业合作系统。

系统不得改变现有内容模型。文章和日记继续共用 `posts`，分别使用既有 `/articles/[slug]` 与 `/diary/[id]` 路由。用户资料继续使用 `profiles`，操作审计继续使用 `admin_logs`，图片继续使用现有 `images` Storage Bucket。

## 2. 已确认原则

- 视觉保持黑色、极简、深夜、柔和，不采用科技仪表盘风格。
- Admin 采用紧凑、可扫描的运营工作台布局。
- 图标统一使用现有图标库中的 Lucide 图标，不再用 emoji 充当功能图标。
- 商业合作总开关默认关闭；所有新增广告位也默认关闭。
- Owner 与 Admin 可以管理业配；Moderator 不可查看或修改商业资料。
- 业配使用照片素材，并始终明确标注“商业合作”和合作方名称。
- 不保存用户级广告行为、IP、阅读记录或广告画像。
- 统计范围为匿名聚合曝光、点击和 CTR。
- 故障或无有效业配时不渲染广告区域，不留下空洞，也不阻断正文。

## 3. Admin 信息架构

侧栏按工作类型重组：

- 运营总览：控制中心
- 社区治理：居民、评论、举报、反馈
- 内容运营：内容、世界公告、全站信件
- 商业合作：业配中心
- 社区成长：徽章、成长记录
- 系统：操作日志、返回首页

权限不只依赖隐藏导航。路由、API 和数据库 RLS 都必须执行相同角色限制。

## 4. 运营总览

### 4.1 时间范围

总览提供四个范围：

- 今日：Asia/Kuala_Lumpur 当日 00:00 至当前时间
- 过去 7 天：按日展示，默认范围
- 过去 30 天：按日展示
- 过去 3 个月：按周展示

范围切换统一影响趋势图和期间指标，并与前一等长期间比较。原始业务数据不因范围变化而删除。

### 4.2 页面结构

桌面端从上至下显示：

1. 页面标题、系统状态、刷新时间、范围切换和刷新动作。
2. 紧凑 KPI：活跃居民、待办、新内容、业配 CTR。
3. 趋势与运营状态。
4. 待处理队列、近期内容、近期居民与业配概况。

移动端要求：

- 系统状态和活跃居民指标之间保留明显间距。
- KPI 使用紧凑的两列布局，降低卡片高度。
- 不依靠横向滚动才能看见关键数据。

## 5. 业配中心

### 5.1 全局控制

业配中心顶部提供：

- 商业合作总开关
- 当前有效业配数量
- 今日曝光、点击、CTR
- 时间范围切换
- 新建业配动作

关闭总开关后，所有前台广告位立即停止返回素材，但草稿、排期和历史统计保留。

### 5.2 业配生命周期

人工状态只保存：

- `draft`：草稿
- `published`：已发布
- `paused`：暂停
- `archived`：归档

后台显示状态根据人工状态和排期计算：

- 待开始：已发布且开始时间在未来
- 进行中：已发布且当前时间位于排期内
- 已结束：已发布且结束时间已过

这样避免依赖定时任务不断修改状态。

### 5.3 编辑字段

- 内部名称
- 合作方名称
- 前台标题
- 简短说明
- 目标网址
- 开始与结束时间
- 投放权重
- 广告位选择
- 各广告位照片
- 每张照片的替代文字

目标网址只允许 `http` 或 `https`。前台外链新窗口打开，并使用 `rel="sponsored noopener noreferrer"`。

## 6. 广告位

支持以下独立广告位：

- 居民首页宽幅
- 故事广场宽幅
- 文章正文中段
- 日记正文中段
- 文章正文结束后
- 日记正文结束后
- 桌面左侧直式
- 桌面右侧直式

左右直式广告位彼此独立，可以分别开关、绑定不同业配和参与轮换。它们只在布局空间足够的桌面视口显示；平板和手机版不显示，也不得覆盖正文。

建议初始桌面安全条件为视口至少 1440px，同时正文保持原有可读宽度和最少 24px 间距。实现时应使用实际容器宽度验证，而非只检查设备名称。

所有广告位关闭、无有效排期或素材加载失败时，原页面自动合拢。

## 7. 正文段落检测与插入

### 7.1 检测方式

正文已经通过 `ReactMarkdown` 渲染。实现应在 Markdown AST 或渲染节点层进行检测，不使用正则表达式拆段。

只把顶层普通正文段落计入自然段数量。以下节点不能作为插入点：

- 标题
- 图片
- 列表及列表项
- 引用
- 代码块
- 表格
- 分隔线
- 其他广告节点

### 7.2 默认门槛

内文广告只有在以下条件同时满足时才成为候选：

- 至少 8 个自然段落
- 至少 1,200 个可见正文字符

这些数字可由 Owner/Admin 在后台调整。

### 7.3 插入位置

系统在全文约 35% 至 65% 的安全段落边界中随机选择一个位置，并避开开头至少 3 段和结尾至少 2 段。

正文未达标时：

- 不强制插入内文广告。
- 仅让正文结束后的广告位进入候选。
- 如果频控仍不允许，本页完全不显示广告。

## 8. 投放与频控算法

### 8.1 默认参数

- 每页最多 2 则广告
- 合格页面基础展示率 60%
- 广告较多的页面后冷却 2 个页面访问
- 最近 10 个页面中，最多 4 个页面含广告

参数可由 Owner/Admin 调整，但界面应提示推荐范围，避免误设为过度投放。

### 8.2 浏览器本地状态

频控只在访客浏览器保存以下有限状态：

- 最近页面是否显示过广告
- 最近页面广告数量
- 剩余冷却页数
- 随机决策所需的短期时间信息

不保存账号 ID、文章 ID、访问内容或可跨站识别的信息。若 Local Storage 不可用，退回当前会话内存，并使用更保守的展示概率。

### 8.3 决策顺序

1. 检查总开关和页面广告位开关。
2. 取得当前排期、状态和素材均有效的业配。
3. 检测正文结构与桌面空间，建立候选位置。
4. 读取浏览器本地频控状态。
5. 根据基础概率、冷却和最近 10 页上限决定本页是否投放。
6. 按后台位置优先级、业配权重和页面广告上限选择位置与业配。
7. 同页尽量避免重复同一素材。
8. 只有广告至少 50% 可见满 1 秒，才报告曝光。

默认位置优先级为内文、文末、左侧、右侧。后台可调整顺序。达到每页上限后，其他已开启位置本次不渲染，但仍可在下一次访问参与轮换。

## 9. 数据库设计

### 9.1 `sponsor_settings`

全站单例配置，包含：

- `commercial_enabled boolean default false`
- 各广告位开关，默认 `false`
- `minimum_paragraphs integer default 8`
- `minimum_characters integer default 1200`
- `max_ads_per_page integer default 2`
- `eligible_probability integer default 60`
- `cooldown_page_views integer default 2`
- `max_ad_pages_per_ten integer default 4`
- 位置优先级
- 时区，默认 `Asia/Kuala_Lumpur`
- `updated_by`
- `created_at`、`updated_at`

数据库约束必须限制合理范围，例如概率 0 至 100、广告上限 0 至 3、门槛非负。

### 9.2 `sponsor_campaigns`

业配主档，包含：

- 主键 UUID
- 内部名称、合作方、前台标题、说明
- 目标网址
- 人工状态
- 开始与结束时间 `timestamptz`
- 投放权重
- `created_by`、`updated_by`
- 时间戳

结束时间必须晚于开始时间。权重必须为正数并设合理上限。

### 9.3 `sponsor_campaign_placements`

业配与广告位关联，包含：

- `campaign_id`
- 受约束的广告位名称
- `image_path`
- `alt_text`
- `enabled`
- 可选的位置专用标题与说明
- 时间戳

`campaign_id + placement` 唯一。删除业配时关联项随之删除。

### 9.4 `sponsor_daily_stats`

匿名每日汇总，包含：

- 马来西亚日期
- `campaign_id`
- 广告位
- 曝光数
- 点击数
- 时间戳

`date + campaign_id + placement` 唯一。CTR 查询时以点击除以曝光计算，曝光为零时返回零。

### 9.5 `private.sponsor_metric_tokens`

服务器专用的短期一次性票据，包含：

- 不可预测的 token 摘要
- campaign 与 placement
- 到期时间
- 曝光是否已计数
- 点击是否已计数

不包含用户、IP 或内容 ID。记录应由定时清理任务删除，且不暴露给 Supabase Data API。

## 10. Storage

不新增 Bucket。素材保存于：

```text
images/sponsors/{campaign-id}/{placement}/{generated-file-name}
```

上传策略：

- 只有 Owner/Admin 可以写入 `sponsors/` 前缀。
- 限制 MIME 类型为支持的图片格式。
- 限制文件容量和像素尺寸。
- 文件名由服务端生成，不能由输入路径覆盖其他文件。
- 删除或替换素材时检查是否仍被其他广告位引用。

## 11. API 与统计

浏览器不能直接读取商业业务表或更新统计。

建议 API：

- `POST /api/sponsors/serve`：接收页面类型、可用位置和匿名本地频控摘要，返回允许公开的素材与短期票据。
- `POST /api/sponsors/impression`：验证票据并原子增加一次曝光。
- `POST /api/sponsors/click`：验证票据并原子增加一次点击，再由前端执行安全跳转。

服务端只返回前台需要的公开字段。票据过期、重复使用、campaign 或 placement 不匹配时拒绝计数。

统计是匿名运营指标，不宣称为跨设备唯一用户数或归因转化数据。

## 12. RLS 与角色权限

- Owner/Admin：读取和管理 settings、campaigns、placements，读取 stats。
- Moderator：无商业表读取和写入权限。
- 普通 authenticated 用户与 anon：无商业表直接权限。
- 统计累加：只允许受控服务端函数执行。
- 私有票据：仅服务端角色可访问。

策略复用现有 `private.is_owner_or_admin()`。所有新建、编辑、暂停、开关和归档动作继续写入 `admin_logs`，`target_type` 使用统一的 sponsor 类型。

## 13. 安全与可访问性

- 所有输入执行服务端 schema 验证。
- URL 拒绝 `javascript:`、`data:` 等非允许协议。
- 前台文案与替代文字转义，不渲染任意 HTML。
- 图片必须有有意义的 `alt_text`。
- “商业合作”不能只靠颜色识别。
- 广告不自动播放、不弹窗、不浮动覆盖、不伪装成居民内容。
- API 使用同源检查、请求体大小限制和基本速率限制。
- 数据库计数函数使用固定 `search_path`、最小 grant 和原子 upsert。

## 14. 失败处理

- 总开关关闭：不请求或不返回任何广告。
- 没有有效排期：不渲染广告。
- 图片加载失败：移除整个广告组件，不留占位。
- 投放 API 失败：正文照常显示。
- 曝光统计失败：不重试到影响页面；可做有限次数后台重试。
- Local Storage 不可用：使用会话内存和更保守概率。
- Admin 保存失败：保留表单内容，显示具体错误，不显示成功状态。
- 统计读取失败：保留其他后台模块，商业指标显示明确错误与重试动作。

## 15. 测试范围

### 单元测试

- Markdown 自然段计数和可见字符计数
- 安全插入点边界
- 短内容文末回退
- 频控冷却、最近 10 页上限、每页上限
- 排期与 Asia/Kuala_Lumpur 日期边界
- URL 和素材验证

随机算法使用可注入的随机源，使测试可重复。

### 数据库与 API 测试

- Owner/Admin/Moderator/居民/anon 的允许与拒绝矩阵
- 总开关与位置开关
- 状态和排期组合
- 票据过期、重复、伪造和位置不匹配
- 曝光与点击原子累加
- `admin_logs` 写入

### 集成与端到端测试

- 新建草稿、上传三种素材、排期、发布、暂停和归档
- 首页、广场、文章和日记的正确广告位
- 文章与日记路由保持不变
- 宽桌面左右栏不压缩或覆盖正文
- 平板与手机版隐藏直式广告
- 内文广告避开图片、代码、列表与引用
- 图片和 API 故障时无布局空洞
- 后台今日、7天、30天、3个月统计一致
- 从真实可见曝光到后台数字更新的完整流程

## 16. 上线顺序

1. 新增数据库结构、约束、RLS、私有函数和 Storage 前缀策略。
2. 上线后台业配中心与运营总览，保持总开关关闭。
3. 上线前台投放组件和正文检测，保持所有位置关闭。
4. 建立测试草稿并完成权限、响应式、频控和统计验证。
5. 由 Owner 手动发布测试业配并逐个开启广告位。
6. 观察错误日志和匿名统计后，再决定是否扩大投放。

紧急回退优先关闭商业合作总开关；不需要删除资料、回滚数据库或重新部署网站。

## 17. 非目标

本阶段不包含：

- 用户级追踪或跨设备识别
- 转化归因、再营销或第三方广告网络
- 自动竞价和广告拍卖
- 付款、账单或合同管理
- 弹窗、插屏、自动播放视频
- 改变文章、日记、评论或用户资料的数据模型
