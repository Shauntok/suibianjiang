# 小时代内容分享功能设计

日期：2026-08-26  
状态：已实施于独立工作树，等待真机验收与合并

## 目标

为公开发布的文章与日记增加统一的分享能力，同时保持小时代的深夜、柔和与慢节奏视觉。

用户可以：

- 复制文章或日记的规范链接。
- 通过手机系统分享面板分享到已安装的应用。
- 预览并分享一张 9:16 的「深夜信纸」Story 图片。
- 在设备不支持图片分享时下载 Story 图片并复制链接。

只有作者明确公开的内容可以使用这些能力。

## 非目标

本阶段不包含：

- 自动替用户发布 Instagram Story。
- Instagram、Facebook 或其他平台账号绑定。
- Meta Content Publishing API 或 OAuth 集成。
- 分享次数统计、排行榜或新的数据库表。
- 将生成图片持久化到 Supabase Storage。
- Push Notification、Email Notification 或分享奖励。
- 重做现有文章、日记或评论系统。

网页只能把链接、文字或文件交给设备的原生分享机制。实际出现哪些应用，以及 Instagram 接收后进入 Story、动态或私信，由操作系统和目标应用决定。

## 方案选择

采用「服务端生成 Story 图片 + 客户端原生分享」方案。

没有采用客户端 Canvas，因为不同设备的中文字体、换行、像素密度和异步分享权限容易产生差异。没有采用 Supabase Storage 预生成，因为这会增加存储、更新失效和清理成本。

Next.js `ImageResponse` 用于按公开内容动态生成 PNG。分享面板会在打开后预加载图片；用户点击分享按钮时，图片已经准备完成，可以直接交给 `navigator.share()`。

参考：

- [Next.js 动态社交图片](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image)
- [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)
- [`navigator.canShare()`](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare)

## 组件与文件边界

### 分享按钮

新增复用组件：

- `components/share/ShareButton.tsx`
- `components/share/ShareSheet.tsx`

`ShareButton` 只负责打开面板与显示当前可分享状态。`ShareSheet` 负责复制链接、原生链接分享、Story 预览、图片分享与下载回退。

组件接收已经存在的文章或日记信息：

- `postId`
- `postType`
- `title`
- `canonicalUrl`
- `isPublic`
- `isOwner`
- 用于图片缓存失效的更新时间

组件不会自行修改内容可见性，也不会向数据库写入分享记录。

### 分享卡接口

新增动态图片接口：

`GET /api/share-card/[type]/[id]`

其中：

- `type` 只接受 `article` 或 `diary`。
- `id` 使用现有 `posts.id`。
- 返回类型为 `image/png`。
- 图片尺寸为 1080×1920。

接口只读取现有 `posts` 与 `profiles`。不新增表、字段或 Storage Bucket。

### 共享逻辑

建议新增：

- `lib/sharing/model.ts`：规范链接、标题回退、Markdown 清理与摘录。
- `lib/server/share-card.ts`：公开内容读取与图片所需数据整理。

文章继续使用 `/articles/[slug]`，日记继续使用 `/diary/[id]`。分享功能不得改变现有路由规则。

## 权限与隐私

分享卡接口必须在服务端重新查询内容，并同时满足：

- `status = published`
- `visibility = public`
- `deleted_at IS NULL`
- `type` 与请求路径一致

任一条件不满足时统一返回 `404`。响应不得透露内容是私密、隐藏、草稿、已删除或根本不存在。

前端的隐藏或禁用按钮只用于体验，不能代替服务端权限检查。

### 非公开内容的按钮行为

- 作者查看自己的私密、隐藏或仅链接可见内容时，显示禁用按钮「公开后可分享」。
- 其他用户通过链接查看 `unlisted` 内容时，不显示分享按钮。
- `unlisted` 访客的喜欢与举报在手机端各占 50%。
- 私密和隐藏内容继续遵循现有访问限制。

## 手机操作布局

### 作者查看公开内容

第一排：

- 喜欢：50%
- 分享：50%

第二排：

- 编辑文章或编辑日记：100%

第三排：

- 返回对应广场：100%

### 访客查看公开内容

第一排：

- 喜欢：33.33%
- 分享：33.33%
- 举报：33.33%

顺序固定为喜欢、分享、举报。举报始终放在最后。

第二排：

- 返回对应广场：100%

### 桌面布局

桌面版只在现有紧凑操作栏中加入分享按钮，不强制等宽，不改变当前编辑与返回按钮布局。

## 分享面板

手机端使用底部面板，桌面端使用小型居中面板。不得使用大型营销式弹窗。

面板包含：

1. 复制链接。
2. 分享到其他应用。
3. Story 图片预览。
4. 分享 Story 图片。
5. 设备不支持图片分享时显示下载图片。

按钮使用 Lucide 图标。复制、系统分享、下载属于明确命令，保留图标和简短文字。

面板需要：

- `role="dialog"` 与可读标题。
- 打开后聚焦面板，关闭后返回分享按钮。
- 支持 Escape 关闭。
- 阻止背景滚动。
- 明确的加载、成功、失败与不支持状态。
- 用户取消系统分享时静默关闭，不显示错误。

## Story 卡视觉

采用「深夜信纸」布局：

- 黑色背景与非常柔和的紫色夜光。
- 小时代书本标记与站点名称。
- 内容类型：文章或日记。
- 标题；无标题日记使用日期标题。
- 作者用户名。
- 开头约 4 至 6 行纯文字摘录。
- 底部显示 `ourlittleage.com` 与规范路径提示。

Markdown 图片、链接语法、标题符号与多余空白会在服务端清理。摘录必须限制长度，避免文字超出 9:16 卡片。

Story 卡不显示私密笔记、未公开字段、管理员信息或完整正文。

## 分享流程

1. 用户点击分享按钮。
2. 面板立即打开，链接操作可立刻使用。
3. 前端请求带内容版本标识的 Story 图片 URL。
4. 图片加载后显示预览，并转成 `File`。
5. 用户点击「分享 Story 图片」。
6. 使用 `navigator.canShare({ files })` 检查设备能力。
7. 支持时调用 `navigator.share({ files, title, text })`。
8. 不支持时下载 PNG，并复制规范链接。

原生分享必须由用户点击触发。系统分享目标由设备决定，界面不能承诺 Instagram 一定出现，也不能承诺自动发布。

## 缓存

2026-08-27 验证修订：Story 图片响应使用 `private, no-store`，每次请求重新检查公开状态，避免作者改为私密后 CDN 继续返回旧图。图片 URL 仍带内容版本参数，优先使用 `edited_at`，否则使用 `published_at` 或 `created_at`。

分享面板直接复用已准备的 File 生成本地预览，关闭时释放对象 URL。无需建立图片清理任务，因为图片不写入 Storage。已被用户下载或发送到其他平台的图片无法撤回。

## 错误处理

- 内容不可分享：接口返回 `404`，面板显示「这篇内容目前不能分享」。
- 图片生成失败：保留复制链接与普通原生链接分享。
- Clipboard API 不可用：使用受控文本选择回退，不暴露内部错误。
- `navigator.share` 不可用：显示复制链接和下载图片。
- `navigator.share` 返回 `AbortError`：视为用户取消，不显示错误。
- 其他分享错误：显示导航栏下方的柔和提示，不改变页面布局。

## 测试计划

### 单元与组件测试

- Markdown 清理、标题回退、摘录长度与规范 URL。
- 公开内容返回图片数据。
- 草稿、私密、隐藏、仅链接可见与删除内容返回 `404`。
- 作者公开内容显示 50/50 喜欢与分享。
- 访客公开内容显示 33/33/33 喜欢、分享与举报。
- 非公开作者显示禁用分享按钮。
- `unlisted` 访客不显示分享，喜欢与举报各占 50%。
- 复制链接成功与回退。
- 支持文件分享、不支持文件分享和用户取消三条路径。

### 集成与视觉检查

- 文章和日记各测试一篇公开内容。
- 400×858 手机视口检查作者与访客布局。
- 检查 Story 图片为非空 1080×1920 PNG，中文不缺字，文字不溢出。
- 桌面视口确认按钮仍为紧凑宽度。
- 验证私密、隐藏、仅链接可见与删除内容无法获取图片。
- 在支持 Web Share 的真实手机上确认系统分享面板可接收 PNG。

## 数据库影响

无数据库修改，无 migration，无新表、字段、RLS Policy 或 Storage Bucket。

## 完成标准

- 公开文章和日记可以复制链接、原生分享及生成 Story 图片。
- 非公开内容不能通过前端或直接接口生成分享卡。
- 手机操作按钮符合作者 50/50、访客 33/33/33 的布局。
- Story 卡能稳定展示标题、作者与开头摘录。
- 不支持文件分享的设备仍能下载图片并复制链接。
- 桌面布局和现有喜欢、举报、编辑、返回功能不回归。
